**El modelo de ciclo de vida en espiral sí es aplicable para terminar un prototipo en tres meses, siempre que se limite el alcance a un MVP (producto minimo viable) y se trabajen ciclos cortos con control de riesgos.**

# Aplicabilidad del Modelo Espiral en un Proyecto de 3 Meses

## 1. Contexto
Nuestro proyecto Bitácora Docente utilizó inicialmente el modelo Sashimi, lo que permitió un avance ordenado al inicio, pero generó problemas en la etapa final debido a integración tardía, falta de mitigación de riesgos y acumulación de retrasos.

## 2. Relevancia del Modelo Espiral
El modelo espiral trabaja por ciclos iterativos que incluyen definición de objetivos, análisis de riesgos, desarrollo y validación. A diferencia de Sashimi, permite ajustar el proyecto conforme surgen problemas técnicos o cambios.

### Beneficios frente a Sashimi
| Problema identificado | Cómo lo aborda el modelo espiral |
|---|---|
| Integración tardía | Entregables funcionales en cada ciclo |
| Riesgos técnicos no gestionados | Evaluación y mitigación constante |
| Dependencias rígidas | Uso de prototipos y mockups por iteración |
| Presión final | Correcciones distribuidas a lo largo del proceso |

## 3. Viabilidad en Tres Meses
Es viable si el objetivo es un prototipo mínimo (MVP) y se ejecutan 3 o 4 ciclos de 2 a 3 semanas, por ejemplo:

| Ciclo | Objetivo | Entregable |
|---|---|---|
| 1 | Arquitectura y base de datos | Modelo de datos y APIs básicas |
| 2 | Integración frontend-backend | Flujo mínimo funcional |
| 3 | Validaciones y usabilidad | Funciones estables para registro y visualización |
| 4 | Ajustes y documentación | Prototipo listo para presentación |

No sería viable si se intenta completar todas las funcionalidades finales o si no se controla el alcance.
